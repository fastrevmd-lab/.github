Thanks for considering a contribution. mechub projects are self-hosted,
sovereign network-security tools; contributions that keep them minimal,
inspectable, and honest are very welcome.

## Before you start
- For anything non-trivial, open an issue first so we can agree on the approach
  before you write code.
- For security vulnerabilities, **do not** open a public issue — see
  [SECURITY.md](SECURITY.md).

## Pull requests
- Keep PRs focused — one change, one PR.
- Match the surrounding code's style; explain the "why" in the description.
- Include tests where the project has them, and note how you verified the change.
- Label maturity honestly: if something is partial or unverified, say so.

## Ground rules
- Deterministic decides, the model explains, a human approves — don't add an
  AI or automation path that makes a safety-relevant change on its own.
- No secrets in commits, issues, or pull requests.
- Be respectful; see [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Licensing
