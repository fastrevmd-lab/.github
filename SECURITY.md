mechub builds security tooling for people who run firewalls, so we take
vulnerabilities in our own code seriously.

## Reporting a vulnerability

Report suspected vulnerabilities **privately** through GitHub's
**"Report a vulnerability"** button on the **Security** tab of the affected
repository (GitHub Private Vulnerability Reporting). This keeps the report
confidential until a fix is available.

**Do not open a public issue for a security problem.**

Include, where you can:
- the repository and the version or commit affected,
- what an attacker can do (impact),
- steps or a proof of concept to reproduce,
- any suggested remediation.

## What to expect

- We aim to acknowledge a report within **3 business days**.
- We will confirm the issue, keep you updated as we work a fix, and credit you
  in the advisory unless you ask us not to.
- These are early-stage projects maintained by a small team. Timelines are
  best-effort, and we will be honest about what we can and cannot fix.

## Scope

This policy covers the code in mechub repositories. It does **not** cover the
third-party firewall, network, or vendor systems these tools interoperate with —
report those to the respective vendor.
